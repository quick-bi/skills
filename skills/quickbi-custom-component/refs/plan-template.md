# 组件实现计划模板

> **何时读**：步骤 1 需求澄清与计划确认（新建组件、改数据契约/视觉/交互前）。

计划写入工程根目录的 `PLAN.md`（还没工程时先在对话里给出，脚手架生成后补写进去）。

## 一、开工前的信息核对

按下表核对用户需求，**缺失项合并成一轮提问**（≤4 个问题，每个问题给出备选项方便用户直接选）；用户不关心的部分直接用默认值，并在计划里标 `（默认值，可改）`。

| 要素     | 需要明确的                                           | 缺失时的默认值                                                                                                                    |
| -------- | ---------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| 组件形态 | 图表类型 / 视觉样式（环形柱图、日历热力图、指标卡…） | **必须问，不猜**                                                                                                                  |
| 数据契约 | 需要几类字段、维度还是度量、各自最多几个             | 按图表类型给最小可用契约（1 维 + 1 度量）                                                                                         |
| 可配置项 | 用户在配置面板能调什么（配色、图例、阈值…）          | 只留 1~2 个高频项                                                                                                                 |
| 交互能力 | 是否支持联动 / 下钻                                  | 有维度就开 `linkage`，drill 不开                                                                                                  |
| 技术选型 | React 还是 Vanilla、用哪个图表库                     | React + 纯 SVG/CSS（简单图形）或 echarts（标准图表），选型阶梯见图表库参考文档；**用户有意向的组件库/帮助文档时优先问并按其意向** |
| 交付边界 | 只本地预览，还是要注册发布到平台                     | 先做到本地预览用户确认通过                                                                                                        |

> 允许在出计划前做的**只读**动作：读 `refs/meta-and-coding.md`（契约权威）、用 `quickbi:list_custom_components` 查平台上同类组件作参考、**联网调研图表库能力（WebSearch/WebFetch 官方文档与示例）**。选型拿不准或用户可能有偏好时，把“有无意向组件库/帮助文档”合进一轮澄清提问。不允许建工程、写源码、装依赖。

## 二、模板正文

以下内容整体复制到 `PLAN.md` 后填充：

````markdown
# 组件实现计划：<组件名>

## 1. 需求理解

一段话复述用户要什么，以及我判断的使用场景（谁在什么报表里用它看什么）。
对需求做的假设逐条列出：`假设 1：…（如不对请指出）`

## 2. 预期效果

- **视觉**：画面上有什么（几个区域、什么形状、配色、数值/标签位置），描述到用户能据此在脑子里画出草图的程度
- **数据变化时**：字段增减 / 数值极端 / 空数据 / 只一行数据时分别长什么样
- **交互**：点哪里发生什么（选中高亮 → 触发联动 → 再点取消）
- **本期不做**：明确排除的范围（如「不做图例点击隐藏系列」），避免预期偏差

## 3. 数据契约（先人话，后 JSON）

### 3.1 用户将看到的字段区域

报表配置面板会出现 N 个拖拽区：

- **「<区域名>」**：拖入什么类型的字段（维度/度量），最少/最多几个，必填还是可选；它在图上决定什么（如「决定环的圈数」）；不填时组件显示什么
- …
  一次最多取 N 行数据，超出时的表现是 …

### 3.2 用户将看到的配置项

样式区会出现：

- **「显示图例」** 开关，默认开；关掉后 …
- **「配色模式」** 下拉，选项「开发（绿色）」「流失（红色）」，默认 …

### 3.3 对应的 meta.ts

```ts
export default { …完整 meta 对象… };
```

> 每个字段区的 `id` 同时是组件里 `encoding[id]` 的取值键，确认后再改名需同步改代码和 mock 数据。

## 4. 实现方案

- 技术选型与理由（一句话）：图表库选什么、为什么不用更轻的方案
- 外部依赖：包名 + 版本 + 是否平台预置（非预置要写明 CDN url 和加载风险）
- 文件清单：哪些文件新建/改动，各自负责什么
- 关键实现点：布局/算法/性能上需注意的 2~3 条

## 5. 执行步骤

- [ ] 脚手架生成（模板：…）
- [ ] 写 meta.ts + 组件实现
- [ ] 构造调试 DSL + 本地预览（用户确认效果）
- [ ] 构建打包
- [ ] 注册上传 + 回读校验

> 标注哪几步需要用户配合（如提供 AK/SK、看效果拍板），以及预估轮次。

## 6. 预览时请确认（交用户拍板）

列出用户在预览页上逐项看一眼就能判断的点：

- [ ] 默认数据下图形形状/配色/标签符合预期
- [ ] 在配置面板关掉「显示图例」后 … 消失
- [ ] 点击数据点后高亮生效，右侧 dispatch 日志出现 `select` 事件
- [ ] 拉伸窗口图形自适应不错位
````

## 三、写计划的硬要求

- 第 2、3 段是给用户看的，**全部用自然语言**；不要用 `maxColNum` / `fieldTypes` / `queryAxis` 这类字段名当描述，换成「最多拖 6 个」「只能拖数值字段」。
- JSON 只在 3.3 出现一次，作为自然语言描述的附录，不要先 JSON 后解释。
- 不写不确定的东西。拿不准就写进「假设」或当面问，不要用模糊措辞掩盖。
- 计划里不写「是否需要我继续？」之类的反问，确认话术统一放在下面的确认闸门。

## 四、确认闸门

计划末尾固定追加一段：

> 以上计划确认后我再开始写代码。你可以直接回复：
>
> - **「确认」** → 我按计划执行
> - **「改 X」** → 指出要调整的部分（如「字段区改成 2 个」「不要用 echarts」），我改完计划再确认
> - **「只做到本地预览」** → 我不做注册发布

用户确认后，把计划第 5 段的步骤转成 todo 清单跟进，每完成一个 Phase 同步勾掉 `PLAN.md` 里的对应项。
